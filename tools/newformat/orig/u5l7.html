Using Technology to Graph and Explore Relations

A graphing calculator or Desmos draws a graph in a second. But the screen only shows part of the plane: the part inside the viewing window. Today we learn to set that window, fix it when something important is hiding, and read intercepts, domain and range right off the screen.

I can…
  • explain what Xmin, Xmax, Ymin and Ymax do, and set a viewing window
  • notice when a window hides an intercept, and choose a better window
  • use the zero, trace, value or table feature to find intercepts
  • read the domain and range of a line from the screen
  • decide the domain and range that make sense in a real situation

Entering a Relation and Setting a Window

The viewing window is a picture frame laid over the plane: only the part of the graph inside the frame appears on the screen. Four numbers control it: Xmin and Xmax (the smallest and largest x shown) and Ymin and Ymax (the smallest and largest y shown).
The standard window is x:[-10,\ 10], y:[-10,\ 10]. We read x:[-10,\ 10] as “x from −10 to 10”.

Graphing it: a TI-84 or Desmos

TI-84
  1. Press Y= and type the right side of the equation. (The equation must start with y=: solve for y first.)
  2. Press WINDOW to set Xmin, Xmax, Ymin, Ymax.
  3. Press GRAPH.
Desmos
  1. Type the equation on an empty line of the expression list.
  2. The graph appears at once. Drag to move around; scroll or pinch to zoom.
  3. Click the wrench icon to type exact window values.

Reading the standard window

Deshawn graphs y=2x+1 and leaves the standard window, x:[-10,\ 10], y:[-10,\ 10], in place.

x:[-10,\ 10], y:[-10,\ 10] · grid lines 2 apart

Adjusting the Window When Needed

If an intercept or another important part of the graph is missing, change the window. Either type a custom window (WINDOW on a calculator, the wrench in Desmos) or zoom out (ZOOM3 on a TI-84; scroll or pinch in Desmos).

Best strategy: work out the intercepts first, then set Xmin, Xmax, Ymin and Ymax a little beyond them, so there is room to spare.
Example 2

A window that hides the intercept

Aisha graphs y=5x-40. Screen 1 uses the standard window; Screen 2 uses an adjusted window.

Screen 1: standard window · grid 2 apart
(a) What problem do you notice with Screen 1?
Almost the whole line is missing. The intercepts are at x=8 and y=-40, and -40 is far below Ymin =-10, so only a short, steep piece shows on the right side. The x-intercept (8,\ 0) is visible, but the y-intercept (0,\ -40) cannot be seen at all.
(b) Determine a better window that shows both intercepts comfortably. State Xmin, Xmax, Ymin, Ymax.
Intercepts first: 0=5x-40 gives x=8; x=0 gives y=-40. Then go a little beyond both, e.g. Xmin =-2, Xmax =12, Ymin =-45, Ymax =10. (Any window holding (8,\ 0) and (0,\ -40) with room to spare is fine.)
Screen 2: x:[-2,\ 12], y:[-45,\ 10] · grid 2 and 5
(c) Does Screen 2 show the full shape of the line, including both intercepts, more clearly than Screen 1? Explain.
Yes. Screen 2 runs from -2 to 12 across and from -45 to 10 up, so (8,\ 0) and (0,\ -40) are both inside the frame with room around them. The relation did not change: only the part of the plane being shown did.

Using Technology to Find Intercepts

An x-intercept is where the graph crosses the x-axis (y=0). A y-intercept is where it crosses the y-axis (x=0). The calculator has tools for both:

zero (or root) finds an x-intercept exactly. TI-84: 2ndTRACE → 2: zero
trace moves a cursor along the graph and shows its (x,\ y).
value gives y at any x you type: x=0 gives the y-intercept. TI-84: 2ndTRACE → 1: value
table lists (x,\ y) pairs. Look for the row with y=0 and the row with x=0. TI-84: 2ndGRAPH

The table: two rows tell you both intercepts

In a table, the x-intercept is the row where y is 0, and the y-intercept is the row where x is 0.

!
Trace is close, zero is exact. The trace cursor jumps from pixel to pixel, so it may land near the intercept but not exactly on it (like x=2.9787). Use zero or value for the exact answer.

Reading Domain and Range Off the Screen

Domain is the set of x-values: scan the graph left to right. Range is the set of y-values: scan it bottom to top.

Runs off the edge
The graph keeps going forever in that direction, past the window.
Stops or turns around
You can see an end: the domain or range is limited.
A straight, slanted line (not horizontal or vertical) runs off the screen at both ends, however far you zoom out. So its domain and its range are both all real numbers: x\in R and y\in R.
Example 4

Domain and range of a line on the screen

The screen shows y=-3x+6 using the standard window, x:[-10,\ 10], y:[-10,\ 10].

x:[-10,\ 10], y:[-10,\ 10] · grid 2 apart
(a) Does the line stop anywhere inside the screen, or does it run off the edges of the window in both directions?
It never stops. It leaves the screen through the top edge (near x=-1.3) and the bottom edge (near x=5.3). There are no endpoints, so the line keeps going forever in both directions.
(b) State the domain of this relation.
All real numbers (x\in R). Every x-value has a point on the line.
(c) State the range of this relation.
All real numbers (y\in R). The line is slanted, so it reaches every height eventually.

A Real-World Relation Explored with Technology

When a relation models a real situation, not every input is allowed: you can’t order a negative number of items. Technology draws the graph and finds the intercepts, but the context decides the domain and range.

Counting things
Only whole numbers make sense (items ordered, people, tickets): the graph is really just dots.
Measuring things
Any value in between makes sense too (hours, kilometres, litres): the graph is a solid line or ray.
No graphing calculator? The scientific calculator works too. Cost of 6 candles: 5+2×6= gives 17. Candles for $23: undo the steps, (23−5)÷2= gives 9.
Example 5

Candles for sale

An online store charges a $5 flat shipping fee plus $2 per candle, so the total cost C of n candles is C=5+2n. The window is x:[0,\ 12], y:[0,\ 30]; red dots mark whole-number n.

x:[0,\ 12], y:[0,\ 30] · grid 2 and 5
(a) Use the trace, table, or value feature to determine the C-intercept (the cost when n=0). What does it represent here?
At n=0: C=5+2(0)=\boldsymbol{5}, so the intercept is (0,\ 5). It is the $5 flat shipping fee: the charge before any candles are added.
(b) Algebraically determine the n-intercept. Does this value make sense as a number of candles? Explain.
0=5+2n, 2n=-5, n=\boldsymbol{-2.5}. No. You can’t order -2.5 candles, and the cost is never $0 because of the shipping fee. The n-intercept belongs to the equation, not to the real situation.
(c) Use technology to determine the cost of ordering 6 candles.
Value or table at n=6: C=5+2(6)=5+12=\boldsymbol{17}. The cost is $17.
(d) Use technology (or algebra) to determine how many candles were ordered if the total cost was $23.
Trace along to C=23, or solve: 23=5+2n, 18=2n, n=\boldsymbol{9}. 9 candles.
(e) State an appropriate domain and range for this relation, given the context.
You can only order a whole number of candles, never a negative number, so the graph is really just the red dots.
Domain: n=0,\ 1,\ 2,\ 3,\ \dots (whole numbers; up to 12 on this screen).   Range: the matching costs C=5,\ 7,\ 9,\ 11,\ \dots ($5 plus $2 for each candle; up to $29 on this screen).
✓

Key ideas

The window is a frame. Xmin, Xmax, Ymin, Ymax decide which part of the plane shows. Standard: x:[-10,\ 10], y:[-10,\ 10]. Changing the window never changes the relation.
Fix a bad window: find the intercepts first, then set the window a little beyond them. y=5x-40: (8,\ 0) and (0,\ -40), so x:[-2,\ 12], y:[-45,\ 10].
Tools: zero finds the x-intercept; value or table at x=0 gives the y-intercept. Trace is close but not always exact.
Domain and range: a slanted line runs off both edges: all real numbers for both. In a real situation the context decides: whole numbers only for things you count.
